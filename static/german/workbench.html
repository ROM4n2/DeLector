如何用 http:// 协议打开（解决 TTS 无声音）

Android 11+ 强制用 content:// 协议打开本地文件，浏览器在此协议下禁用了 TTS API。需要切换到 http:// 协议：

方案 A：电脑跑本地服务器（最推荐，零依赖）

  1. 电脑 cmd 进入 workbench.html 所在目录
  2. 执行：python -m http.server 8000
  3. 手机连同一 WiFi，浏览器访问 http://电脑IP:8000/workbench.html
    （电脑 cmd 执行 ipconfig 看 IPv4 地址，如 192.168.1.100）

方案 B：部署到免费静态托管（永久可访问、跨网络）

  1. GitHub Pages：上传 workbench.html 到 username.github.io 仓库
  2. Cloudflare Pages / Vercel：拖拽上传即可
  3. 访问 https://your-name.github.io/german/workbench.html

方案 C：手机装本地 HTTP 服务器 app

  1. Play Store 搜 "Tiny Web Server" 或 "Simple HTTP Server"
  2. 把 workbench.html 放到 app 指定目录
  3. 浏览器访问 http://127.0.0.1:8080/

切换到 http(s):// 协议后，所有 TTS API（在线 + Web Speech）都能正常工作。

多设备使用指引

电脑（主设备）：双击本 HTML 文件即可使用，进度自动保存在浏览器本地。
手机（辅助设备）：把本文件通过微信 / 网盘发送到手机，用系统浏览器或 Chrome / Edge / Firefox 打开； 微信内置浏览器可能限制本地存储，请选择「用其他应用打开」。
双端同步：在旧设备「导出同步文件」→ 传到新设备 → 新设备「选择文件」导入（合并模式）。 每张卡按最近复习时间自动取较新的一方，不会旧盖新。

LAN 同步（6 位短码，WebRTC P2P）

两台设备在同一局域网内，通过 6 位短码即可点对点极速同步进度与词库。
流程：A 设备生成短码 → B 设备输入该短码并生成回执 → A 设备输入回执短码 → 自动传输并合并。
—
—

③ 等待 A 输入你的短码，传输完成后自动完成合并。

关于复习算法

本工作台采用 FSRS-6（Free Spaced Repetition Scheduler，开源项目 open-spaced-repetition）， 使用官方默认参数，无需训练。每张卡维护「稳定性 S」与「难度 D」： 「认识」会拉长下次复习间隔，「不认识」按遗忘曲线重置较短间隔，「模糊」介于两者之间。 间隔按期望留存率计算，逾期复习会按实际遗忘程度修正。数据完全保存在本机浏览器 localStorage 中。

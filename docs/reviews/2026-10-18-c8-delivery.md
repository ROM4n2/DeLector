### 关键设计决策（都有实测依据）

1. **`GET /api/settings` 不是「未脱敏」而是「缺来源闸」**（登记表描述有误，已修正）。端点本就做静态掩码；真缺陷是任何 LAN 来源都能读到它。修法是**按来源收敛**而非加 `_require_localhost` 整门——后者会把局域网手机端的设置面板整个打掉（前端 `static/js/main.js` 依赖这些字段）。`_is_loopback_origin` 的判定元组与 `_require_localhost`（`delector/core/database.py:67-85`）**逐字相同**，且同为 fail-closed。
2. **`.gitignore` 收窄是精确的而非近似**：PyInstaller 以 `cwd=root_dir` 运行 ⇒ 产物**就是**根目录的 `DeLector.spec`。
3. **`gitleaks-action@v2 → @v3`**：v2 依赖 Node 20 运行时，已被 GitHub 于 **2026-09-16** 从托管 runner 完整移除（v3.0.0 release note 明载）⇒ v2 当日起**无法运行**。此偏离由复核方从一手来源独立证实。

## 二、附带交付的新机械闸（本批最持久的资产）

`tools/check_silent_degradation.py` —— 把「静默降级」这一类缺陷从**逐案修复**升级为**执行路径上的机械闸**。

- **判据按机制形状而非字符串匹配**（AST/tokenize）：C1 = 块体仅为 `pass` 的 except；C2 = 裸 `except:`；C3 = TLS 校验禁用且同函数内无日志调用。
- **抑制必须带具体理由**（`silent-ok: <理由>`，空理由本身即违规）。
- **退出码契约** 0=通过 / 1=有违规 / 2=环境不可用（与 `check_master_commit_scope.py` 同形）。
- **变异自证**：植入 `except: pass` ⇒ exit 1 并点名 `file:line`；移除 ⇒ exit 0。

### 首扫 STOP CONDITION 与裁决（**这是本闸最重要的设计记录**）

首扫命中 **32 处 > 20** 阈值 ⇒ 实现方**停止并上报，未做任何批量豁免**（按 `mechanical-gate-authoring` 的反稀释规则：超过某个数量，闸就从「编码一条规则」退化成「给代码库拍快照」）。编排者裁决后的账目**可审计**：

```
原始 31 C1  =  收窄掉 8（continue 形态）+  修掉 4（加日志 ⇒ 不再命中）+  豁免 19
```

- **收窄有机制理由**：`pass` 把一条错误路径**整个掐灭**；`continue` 是循环内的**逐项策略**，其余迭代照常执行。
- **收窄的已知极限被诚实登记**在闸头注释里（不指望 C1 兜底「逐项跳过掩盖系统性失败」那一类；发现时另立判据，**MUST NOT** 靠重新放宽 C1 了事）。
- **收窄不许成为藏事故的手段**：第 5 个真事故 `main.py:1250` 落在「收窄掉」的那 8 处里，**仍然被修**。此点已写进提交信息。

## 三、评审结论

四批各自经过**独立对抗性评审**，全部 **PASS，零 Red Card**。评审方的复核深度超出要求，贡献了多个未被要求的硬事实：

- `HTTPException` 与 `httpx.HTTPError` **无继承关系**（`issubclass` 双向 False）⇒ `_shelf_get` 内层 `raise` 的 502 不会被 `except` 吞掉（用真实本地服务器端到端证实）；
- 无 `Content-Length` 的 4MB 流在客户端读到 **2,359,296 / 4,194,304 字节即被截断** ⇒ 上界作用在**读循环内**而非缓冲之后；
- `gitleaks-action` 的 `if:` 闸**确实有效**（溯至 action 源码：`--log-opts` 只在 push/PR 传入，其余事件退化为全历史扫描）；
- **`.gitleaks.toml` 的失效模式是 FAIL OPEN** —— 配置键拼错 ⇒ viper 静默忽略 ⇒ 零规则 ⇒ 带密钥也全绿。承重键真实性已被独立核实；
- 19 处豁免**逐条读过，无一粉饰活缺陷**。

### P0-2 桌宠 P2：遮挡、禁停区、落点避让

**设计裁决（需要用户确认）**：两份调研存在冲突——`companion-bubble-and-vitality-research` 主张「禁停区 + 自动避让」，`writer-mobile-layout-research` §7.2 主张「编辑态隐藏桌宠」。本计划采用融合方案：

1. **编辑态让位优先**：输入框聚焦、选区存在、软键盘弹起时，桌宠淡出或移到安全角，不做逐帧避让。
2. **非编辑态禁停区**：`.writer-sidebar`、底部音频托盘、抽屉/面板（z-index 1100）、顶部工具栏、以及正文可点击区域，一律作为障碍矩形。
3. **禁止抬 z-index 压 sheet**：桌宠层级不得高于 1100；冲突时桌宠让位。

**验收标准**

- 阅读面：桌宠不得覆盖正文 token；阅读页不因本项新增任何动画；正文区域零布局位移。
- 功能面：写作页任意滚动位置下，桌宠不覆盖输入框、选区手柄、发送键、底部托盘；点击穿透区不出现「点正文点到桌宠」；sheet 打开时桌宠不可见或位于 sheet 之下；360×800 与 393×852 两档视口下桌宠完整可见（右/下边界不越界）。
- 落地页：不触碰。
- 工程：落点选择抽成纯函数（输入：视口、障碍矩形、当前点；输出：合法点），单测覆盖「无解时回退到默认角」「障碍动态增减」「视口 resize」；CDP 几何探针钉住上述三档断言。
- 停止门：若融合方案在真机上仍出现键盘遮挡，停止并回报，不回退到「抬 z-index」方案。

**真机项**：软键盘弹起后的 `visualViewport` 与 WebView 行为必须真机验证；模拟器只能验证无键盘场景。

### P1-1 备考页数字单位 + 契约

**验收标准**

- 功能面：A1 五个模块分别显示「18 题 / 5 套 / 5 套 / N 题 / 702 词」；A2、B1 词表显示「N 词」；360px 宽度不换行、不溢出；数字使用既有 mono 12 元数据样式，不新增字号。
- 落地页：不触碰。

### P1-2 写作区选区 agent 操作条

**前置**：先出交互规格（放 `docs/specs/`），明确操作项、接受/拒绝语义、失败态；规格确认后再实现。必须复用既有 proposal/HITL 协议，不得新开第二条写入链路。

**验收标准**

- 阅读面：操作条不得覆盖选中文本；出现/消失不得引起正文重排；正文零动画。
- 功能面：选中文本后 8–12px 内出现操作条，边界自动翻转；「改写 / 解释 / 存卡片」三项可达；接受只替换选区，拒绝与失败不改正文；操作条层级低于 sheet 1100、高于底部托盘；360px 下不溢出；键盘弹起时自动上移且不遮挡选区。
- 落地页：不触碰。
- 工程：写入走既有 proposal 端点；失败必须可见（禁止静默）；新增纯逻辑有单测；真机触摸选区手柄需验证。
- 停止门：若现有 proposal 协议无法承载「只替换选区」，先停下改协议设计，不在前端硬拼。

**真机项**：软键盘 + 选区手柄 + 长按菜单三者叠加必须真机验证。

### P1-3 桌宠 P3：状态机

**范围**：`idle / thinking / acting / speaking / waiting / dragging / sleeping / error`。状态必须由真实事件驱动，禁止用定时器伪造「思考中」。

**验收标准**

- 阅读面：状态变化不得影响正文；`speaking` 不得在阅读页自动播放音频。
- 功能面：任一时刻只有一个 `data-state`；`thinking/acting/speaking` 必须对应真实 SSE/请求生命周期；请求结束 500ms 内回落到 `idle`；`error` 有可读文案且可恢复；`prefers-reduced-motion` 下所有状态动画静止为终态；页面隐藏时暂停；不新增循环动效（白名单仍为 7）。
- 落地页：不触碰。
- 工程：状态迁移表进单测；非法迁移（如 `idle → speaking`）必须被拒绝；CDP `getAnimations()` 验证 reduce 模式下无运行中动画。
- 停止门：若后端事件不足以区分 `thinking` 与 `acting`，只做可证实的 4 个状态，不造假状态。

**真机项**：`dragging` 与触摸滚动冲突需真机验证。

### P1-4 Android 存量文章重算

**范围**：提升 `PROCESSED_JSON_VERSION`（当前 3.5.0），让旧文章按需惰性重算；不新增「启动全量重算」。

**验收标准**

- 阅读面：旧文章打开后，格位/词性标注与新处理结果一致；抽样句（含 `Bücher` 类格位）改前/改后逐 token 对比，正确结果不得被改错。
- 功能面：打开单篇长文时显示处理中状态；不得在启动时批量重算；失败必须可见并保留旧结果；Android 上不得 OOM。
- 落地页：不触碰。
- 工程：单测覆盖「旧版本 → 触发重算」「新版本 → 不重算」「重算失败 → 旧数据仍可读」；模拟器实测单篇耗时与 PSS 峰值，数据写进 PR 描述，不改 ADR-0028 的既有残余风险口径。
- 停止门：模拟器实测峰值显著高于 ADR-0028 §4.2 记录的 700 MiB，停止并回报，不硬推。

**真机项**：arm64 与低端机内存表现无覆盖，必须如实标注。

## 3. 串行与并行编排

### 硬串行（不可同时开 worktree）

1. **发布裁决先于新合并**：`v5.22.0` 从当前 `origin/master` 切 tag。发布验证期间冻结 master 合并；发布后再合新 PR，避免把半成品带进版本。
2. **`style.css` 单所有权**：P0-2 桌宠 P2 → P1-2 选区操作条 → P1-3 状态机 → P1-6 焦点环 → P2-1 小扫，按此顺序串行，禁止两个 worktree 同时改 `style.css`。
3. **P1-2 必须先有规格**：规格未确认不得开工；且必须在 P0-2 之后，复用同一套浮层/禁停区规则。

### 可并行（不同文件所有权）

- P0-1 发布验证（只读 + 版本面）与 P0-2 桌宠开发可并行，但合并顺序为发布在前。
- P1-1 备考 unit（`exam_catalog.py` + `main.js` + 测试）可与 P0-2 并行。
- P1-5 端口互斥（Go + `go_agent_supervisor.py` + 测试）可与任意前端并行。
- P1-4 Android 重算（`processor.py` + 版本号 + 测试）可与前端并行，但需单独占模拟器窗口。

**并发上限建议 2 个开发 worktree + 1 个发布验证**。超过 3 个会重新引入 `style.css` / `main.js` 合并冲突。

### 推荐波次

- Wave 0：发布 `v5.22.0`（冻结合并）。
- Wave 1：P0-2 桌宠 P2 ｜ P1-1 备考 unit ｜ P1-5 端口互斥。

| 播放器托盘音色切换 / 系统 TTS 降级 | 模拟器可部分验证，音色集合与真机不同 | **必须真机** |
| `prefers-reduced-motion` 系统级开关 | Edge headless 可模拟，Android 系统开关无 | 真机补充 |
| Android 低端机 OOM / 内存峰值 | 无低端机 | **无覆盖** |
| arm64 真机 APK | 只有 x86_64 模拟器 | **无覆盖** |
| iOS Safari | 无 | **无覆盖** |
| 真实屏幕阅读器 | 无 | **无覆盖** |
| 真实 DeepSeek API 链路 | 本地 key 401 | **无覆盖**，模型标识类改动一律搁置 |

## 5. 不建议做（含理由）

| 项 | 结论 | 理由 |
| --- | --- | --- |
| 桌宠 P4 自由移动 | 本批次不做 | 默认关闭、需求未证实；拖拽会把「禁停区/落点避让」的冲突面翻倍，应先让 P2/P3 稳定 |
| `.deck-active-card` 按压反馈 | 不做 | 该卡已有滑动手势 transform，叠加 press feedback 会与手势判定互相覆盖；收益仅是手感，风险高于收益 |
| `🎴` 单独立项 | 不单独立项 | 只在两条 HTML 注释里，不渲染、不影响 I1 判据；折进下次 `cards.js` 改动即可 |
| 全站 `#15803d` 批量替换 | 不做 | 8 处里只有 `is-covered` 语义明确是「已覆盖」；其余可能是考试对错色，整批换会改变语义 |
| 全站 focus 清理 / 图标集扩展 / 角色 SVG 化 | 不做 | ADR-0029 已明确延后；无视觉回归测试，容易引入不可见回归 |
| 修改 Go 默认模型标识 | 不做 | 本地无有效 key（401），且历史经验显示模型标识改动会直接 400/422；无验证手段前不得改 |
| 用缩小模拟器内存「模拟低端机」 | 不做 | ADR-0028 明确写入「不得把低端机当作已覆盖」；缩小内存不能替代真机证据 |
| 为 OOM 提前加降级/关模型 | 不做 | 违反 D4 硬失败与「宁漏勿错」；无证据的降级会把「标错」换成「静默不标」 |
| 再改播放器音色控件 | 不做 | 托盘刚重构完成，尚无使用数据；继续改只会 churn |
| 把桌宠 z-index 抬到 sheet 之上 | 不做 | 会制造「浮层压浮层」的新遮挡；正确方向是桌宠让位 |
| 发布前顺手做新功能 | 不做 | 会扩大发布回归面；发布窗口只修发布阻塞项 |

## 6. 结论

**先做两件：**

1. **立即发布 `v5.22.0`**：把 #272–#279 已合并的用户可见修复交付出去。这是当前最高性价比动作，且不依赖任何未完成项。
2. **发布后立刻做桌宠 P2**：这是目前唯一一个「用户能感知到、且根因已定位」的功能缺陷（挡点击、挡正文、键盘遮挡），范围可控，且是 P3 与选区操作条的前置。

**明确不做**：桌宠 P4、全站视觉批改、模型标识改动、无设备条件下的内存/真机结论。这些看起来该做，但要么收益低，要么与既有设计冲突，要么根本无法验证。

**需要用户拍板的一件事**：桌宠 P2 采用「编辑态让位 + 非编辑态禁停区」的融合方案，还是坚持纯禁停区（不隐藏）。我推荐融合方案，理由是它同时满足两份调研，且避免抬 z-index。

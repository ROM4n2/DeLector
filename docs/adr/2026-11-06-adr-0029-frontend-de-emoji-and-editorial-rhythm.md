## 1. 背景

第一轮调研测得：`static/` 与 README 共 551 个 emoji 簇，523 可见，其中 382 个（73%）删除后语义不丢失。第一轮据此提出：

- P0：删掉 382 个冗余 emoji；
- P1：把 83 个「唯一信息载体」换成 inline SVG；
- P2：向 `tokens.css` 注入间距/字号/行高阶梯，收敛 11 种 line-height 与 78 处 11px。

第二轮补充了外部证据：6 个同类产品里 5 个落地页零 emoji；6 个工程型 README 标题 emoji 为 0/6；GOV.UK 明确「一个图标不得表示两件事」。同时更正了两个数字：`aria-label` 不是 0（源片段 11 处，但没有一处作用于 emoji），README 是 10/10 个二级标题带 emoji。

本 ADR 对上述 P0/P1/P2 逐条拷打后重新收敛。

## 2. 拷打记录（Dual-Lens）

### Lens A：用户与产品体验

**A1「删 382 个是不是为了不像 AI，牺牲可用性？」**
是，如果按原提案一次性删。382 这个数字来自「删除后语义是否丢失」的启发式分类，而 58 个「介于两者之间」正是分类置信度最低的区间。实测反例有三类：

- `companion.html:129-134` 的 `#panel-sound` 按钮内容只有 `🔊`/`🔇`，无 `aria-label`、无可见文字——删掉就是功能消失；
- `companion.html:27-34` 的角色按钮只有 `🦉`，靠 `title="歌德猫头鹰"` 兜底，触屏无 tooltip；
- `cards.js:133` 的三态 `🎉/🛡️/🎴` 无任何文字，删掉后用户无法区分「到期/已掌握/新卡」。

所以「382」不是一批，至少含三类**不得直接删**的子集。原 P0 的一刀切不成立。

**A2「83 处换 SVG 值不值？」**
原提案隐含「一处 emoji = 一个 SVG」，这是成本误判。83 处出现在 41 个文件里，但很多位置本来就有中文标签（`nav_mobile` 8 处、`exam.html` 7 处、`a1_hoeren` 2 处）。这些位置的正确动作是**删字形、留文字**，成本为 0。真正需要图形的只有「无可见文字的控件」，实测至少包括：

- `#panel-sound` 静音切换（1 个）；
- 播放/暂停类控件（`player` 相关）；
- 可能的状态指示（需在开工前跑一次「无文字且承载语义」的精确清单）。

按最坏估计也就是 12–20 个唯一图形，而不是 83 个。**先做 8–12 个图标的集合，不做 83 个一次性替换。**

**A3「去掉 emoji 后靠什么不死板？」**
外部证据给出的答案是：低信息密度 + 每节只讲一件事 + 图片/截图承担视觉趣味。对本项目，可执行的是：section 间距 40–64px、正文行高 1.6、长读 1.9、行宽 45–90 字符（CJK 40 字）、卡片内 padding 16–24px、空状态用「细线 + 衬线标题 + 一句说明」。这些是 5 个界面的具体数值，不是全站 token 工程。

### Lens B：技术与工程实现

**B1「tokens 阶梯化是不是过度工程？」**
部分是。11 种 line-height 与 78 处 11px 里，有相当一部分是**密集桌面表格的合理选择**，不是错误。真问题是 4.8/5.6/6.4px 这类**不在任何网格上的间距**，会造成视觉抖动。但把全站迁移到 token 需要改 41 个文件，且项目没有视觉回归测试，回归风险高于收益。结论：**新增 token，不强制迁移**；只在 nav / cards / reader 三个高频面迁移，其余新代码用 token、旧代码不动。

**B2「顺序对不对？」**
原顺序「先删再补排版」把最难回退的一步放在最前。若 P0 做完发现页面变空，必须立刻做 P2 才能恢复，而 P2 又是风险最高的一步。改为：**先在一个垂直切片上建立替换语法，再批量推广**。切片选 `exam + nav_mobile + cards 状态 + companion 声音/角色按钮`——emoji 密度最高、语义碰撞最集中、且能覆盖「删/换/补」三种动作。

**B3「范围该不该一次做完？」**
不应。四个决策彼此独立：

| 决策 | 性质 | 依赖 | 可跳过 |
|---|---|---|---|
| A 删装饰性 emoji | 审美 + 噪声 | 无 | 否（但可分两批） |
| B 给无文字控件补可访问名 | 功能 + 无障碍 | 无 | 否 |
| C 建 8–12 个图标集 | 基础设施 | B | **可以**（B 用文字标签也能过） |
| D 重写 README | 对外沟通 | 无 | 可以延后，但 ROI 最高 |

C 不是 A/B 的前置条件；D 与代码完全解耦。原 P1 把 B 和 C 捆在一起，导致成本被高估。

**B4「构建链与 Android 各多付什么代价？」**
inline SVG 只是 HTML/JS 字符串，不新增请求，`tools/build_index_html.py` 的 `@include` 与 `tools/sync_android_sources.py:84,117` 的整树复制都不需要改。项目无 CSP（全仓仅调研报告提到该词），inline SVG 不受限。若改用 sprite，会多一个同源文件与一次请求，`static/sw.js` 是运行时缓存、无 precache 清单，首屏可能 404 一次再回源——成本高于 inline。图标字体要 20–80KB 且 PUA 码位易撞、首屏 FOUT，否决。CSS mask 需要 `-webkit-` 双写且纯背景无语义，只在「纯装饰、颜色随 currentColor」时可用。

**B5「什么情况下这个方向是错的？」**
见 §6 的可观测失败信号。最短版本：**如果删完之后某个控件没有可访问名，方向就已经错了；如果 token 迁移让未被要求改的页面出现 >5% 视觉差异，方向也错了。**

## 3. 决策

1. **不变量改为「任何字形都不得是意义的唯一载体」，而不是「emoji 数量归零」。** 这是本 ADR 与第一轮提案最根本的区别。
2. **四个决策拆开做，顺序 D → A+B → C。** README 先改（零代码风险、面试官可见），再做语义卫生，图标集最后且可跳过。
3. **不做 83 个 SVG。** 只做一个 **≤12 个图标**的集合，仅用于「无可见文字的控件」；有文字标签的位置一律删字形、留文字。
4. **垂直切片先行。** 第一切片 = `exam.html` + `nav_mobile.html` + `cards.js` 状态 + `companion` 声音/角色按钮；验收通过后再推广到其余 37 个文件。
5. **tokens 只增不迁。** 在 `tokens.css` 新增间距/字号/行高/动效 token；只迁移 nav / cards / reader；不扫 78 处 11px。呼吸感通过这 3 个面的具体数值实现，不依赖全站 token 化。
6. **受保护字形白名单**：角色身份（🦉🐱🦊🤖，待 SVG 化）、声音开关、播放控件、任何在替换落地前仍是唯一标签的字形。白名单内的字形不进 A 批删除。

## 4. 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 一次性删 382 个 | 58 个「介于两者」分类置信度低，且含 icon-only 控件与角色身份三类保护对象；一刀切会把「去 AI 味」做成「去功能」 |
| 83 处逐一换 SVG | 大量位置已有文字标签，换 SVG 是把噪声换成更贵的噪声；唯一图形需求 ≤20，做 12 个足够 |
| 图标字体 | 20–80KB、PUA 码位碰撞、首屏 FOUT、无障碍最差 |
| SVG sprite + `<use>` | 多一次请求、多一个文件；本项目无 precache，收益不抵成本；12 个图标 inline 更简单 |
| 全站 token 迁移 | 无视觉回归测试，41 文件改动，回归风险高于收益；且「呼吸感」不需要 token 化就能实现 |
| 保持现状不动 | `exam.html` 的 7 模块 6 图标、`#panel-sound` 无可访问名、`🇩🇪/🇨🇳` 在 Windows 退化，都是与审美无关的实缺陷 |
| 把 emoji 保留为品牌语气 | README 与产品界面不保留；版本日志/社交文案可另行讨论，不在本 ADR 范围 |

## 5. 实施顺序（替代原 P0/P1/P2）

### D（先做，1–2 小时，零代码风险）
- README：删 10 个标题 emoji；去掉非术语性的英文括注；8 个徽章下移到技术栈；「核心特性」取消全量粗体。
- 新增一节「什么场景不该用 DeLector」。
- 验收：`^## ` 行 emoji 数为 0；粗体对数 ≤30；首屏第一屏只出现标题 + 一句话 + 两张截图。

### A（第一批：可安全删除，约 1 天）
- 只删「同一行内已有等价中文/德文」的 emoji；`#panel-sound`、角色按钮、卡片三态等进入 B。
- 验收：删除后每个可见控件仍能通过文字或 `aria-label` 被命名。

### B（与 A 同批，约 1 天）
- `#panel-sound`：加 `aria-label="伴读发声"` + `aria-pressed`；字形加 `aria-hidden="true"`。
- 角色按钮：`title` → `aria-label` + `aria-pressed`。
- `cards.js:133` 三态：文字徽章 + 颜色 + 3px 左竖线。
- `a1_hoeren.js:508-509`：`🇩🇪/🇨🇳` → 等宽 `DE`/`ZH`。
- `exam.html:12-18`：`01`–`07` 编号 + 中文 + 德文。
- 验收：`aria-hidden` 从 0 起有覆盖；无文字控件的可访问名覆盖 100%。

### C（可跳过后置，0.5–1 天）
- 只做 ≤12 个 inline SVG，用于仍无文字标签的控件。
- 开工前先跑一次脚本，产出「无文字且承载语义」的精确清单；若清单 ≤12 则做，超过则先补文字标签。
- 验收：新增 SVG 总体积 ≤12KB；每个 SVG 有 `aria-hidden` 或 `role="img"` + `aria-label` 二者之一。

### Token（独立，不阻塞 A/B/C）
- `tokens.css` 新增 `--sp-1…--sp-8`、`--fs-xs…--fs-xl`、`--lh-ui/body/read`。
- 只改 nav / cards / reader 三个面；其余不迁移。
- 验收：这三个面无 5.6/6.4/4.8px gap；其他页面 0 改动。

## 6. 可观测失败信号（出现任一即停）

1. 任一控件在删除字形后既无可见文字、又无 `aria-label` / `aria-pressed`。
2. token 迁移导致未被要求修改的页面出现 >5% 视觉差异（截图对比）。
3. 三个独立评审者对同一面给出「删完更空、像没做完」的判断，而该面尚无排版替代。
4. README 删 emoji 后总行数上升而标题数不变（用散文填补，方向反了）。
5. 图标集超过 15 个或总体积超过 12KB（范围蔓延）。
6. 第一切片验收超过 3 天仍未收敛（说明替换语法没想清楚，应回退到设计而非继续铺开）。

## 8. 后果

**正面**：把「去 AI 味」从审美争论变成三条可测判据（无文字控件是否被命名、一图是否一义、跨平台字形是否稳定）；成本从「83 个 SVG + 全站 token」降到「1 个切片 + ≤12 图标 + 3 个面」；README 改动零风险且最先被面试官看到。

**负面**：第一切片期间，exam/nav/cards/companion 与其余页面会短暂视觉不一致；若采用分支方式可避免上线期不一致，但评审期仍会看到差异。

**未解决**：83 处里到底有多少个唯一字形、其中多少真的无文字标签，仍需开工前跑一次精确清单。本 ADR 的 ≤12 是**上限估计**，不是实测值。

## 11. 有效期与失效条件

### 11.1 本 ADR 的证据基线

本文所有「已实测」结论都来自 2026-11-06 的快照，**不是永久事实**：

- `static/` + README 共 551 个 emoji 簇（523 可见 / 28 注释）；去重源片段 380；唯一字形 86。
- 382 个（73%）删除后语义不丢失；83 个信息载体；58 个介于两者。
- `static/` 源片段 `aria-label` 11 处，其中**服务于字形符号的为 0**；`aria-hidden` 0；`sr-only` 0。
- README 二级标题 10 个，**10 个带 emoji**；段落最长 1257 字符。
- 外部基线：6 个同类产品 5 个落地页零 emoji；6 个工程型 README 标题 emoji 为 0/6。

### 11.2 失效条件（满足任一，本 ADR 即应被判为失效）

| # | 条件 | 判据 | 为什么会使本文失效 |
|---|---|---|---|
| E1 | emoji 基数显著变化 | 重新扫描得到的总簇数相对 551 变化 **超过 ±20%**（即 <441 或 >661） | 分层比例（73/16/11）可能整体漂移，原删除清单不再可信 |
| E2 | 第一切片验收失败 | §6 任一失败信号触发，或切片 3 天未收敛 | 「垂直切片先行」的核心假设被证伪，顺序决策需重开 |
| E3 | 无障碍基线已满足 | 装饰性字形 `aria-hidden` 覆盖 100%，且不存在「无可见文字 + 无可访问名」的控件 | 本 ADR 的**功能性与无障碍理由**已消解，只剩审美清理，应按新目标重新定级 |
| E4 | 构建链变化 | `tools/build_index_html.py` 的 `@include` 机制或 Android 整树复制被替换；或项目新增 CSP 且禁止 inline SVG | §3.4 / §2.B4 的成本结论建立在当前构建链上 |
| E5 | 更优图标方案出现 | 出现原生 SVG symbol、设计系统内置图标组件，或 Android WebView 对 `currentColor` 的实测否决 inline SVG | §3 的「≤12 个 inline SVG」选型被推翻 |
| E6 | 无障碍规范升级 | WCAG 新增/收紧与图标相关的成功准则（如非文本对比度、目标尺寸），且适用于本项目 | §3.2 的 6 条清单可能不再是最低限度 |

### 11.3 失效后怎么做

1. **不修改本文**，在顶部状态行追加 `Superseded by ADR-00XX（日期）`。
2. 新建 ADR，标题写明取代关系，正文逐条列出：
   - 旧 ADR 哪几条失效（引用 §号）；
   - 依据什么证据失效（数字 / 实测 / 外部规范）；

## 12. 推翻留痕机制

> 原则：**ADR 是受限于当时证据的决策，后续可以推翻。** 推翻不是删除，是留下可追溯的替代链。

### 12.1 状态词表（固定四态）

| 状态 | 含义 |
|---|---|
| `Proposed` | 已写出、未拍板 |
| `Accepted` | 已拍板、生效中 |
| `Superseded by ADR-00XX` | 已被新 ADR 取代；正文保留 |
| `Deprecated` | 不再适用，且没有替代 ADR（需在正文写明原因） |

### 12.2 四条硬规则

1. **原文不改写、不删除。** 只允许在顶部状态行追加取代标记，以及在文末追加「修正记录」段。
2. **新 ADR 必须显式引用旧 ADR。** 头部写 `Supersedes: ADR-0029 §x`，正文写失效理由与证据。
3. **同一 PR 更新索引。** 新增 / 取代 / 废弃 ADR 时，`docs/adr/INDEX.md` 的状态列必须同步改；否则 PR 不合规。
4. **计划偏差必须落表。** 执行阶段若发现某条结论不成立，写入计划的 `Deviation Table`，并在 ADR 追加「修正记录」，不得静默改写任务。

### 12.3 索引现状

- 截至 2026-11-06，`docs/adr/` 有 29 份 ADR，**没有索引文件**；状态写法也不统一（`Accepted` / `ACCEPTED` / `Proposed`）。
- 已有机制是 `docs/README.md` 的目录说明，但它只说明「ADR 放哪」，不回答「哪份仍生效」。
- 结论：**值得建一份最小索引** `docs/adr/INDEX.md`，列 `编号 | 标题 | 状态 | 取代/被取代 | 日期`，只做状态视图，不复述内容。成本是一张 29 行表；收益是任何后续 ADR 都能一眼看出继承链。该任务列入计划 T0。

### 16.2 失效与推翻原文（4 条）

> 以下 4 条按 §12.2 规则 1 记为**失效/判错**：原文保留，替代口径写在这里。

#### 16.2.1 `section/content = 4.0` 从未落在像素上

- **原文**：外部参考评审把 `section/content` 间距比目标写作 **4.0**（`docs/research/2026-11-06-emoji-vs-typography-prototype.html` 的配套原型）；§3.5 据此落成「section 间距 40–64px」。
- **实测**：该原型实际渲染是 **64 ÷ 40 = 1.6**；4.0 是按「section = 元素 × 2.5–3」倒推的**合成目标值**，从未落在任何像素上。T9 实测功能面内部块间 28–32px（1.17 档），阅读面 70 字符/行、1.85 sans / 1.95 serif。
- **结论**：**【失效】** 4.0 不能作为验收常数。替代口径按作用层拆分：
  1. 阅读面（reader 正文块）保持现状；
  2. 功能面（cards 控制区、exam 列表）内部块间 28–40px 是刻意紧凑，不是欠账；
  3. 只有 `.view` 级 padding 维持 40/64。
- **留痕**：计划 §7 #10；`WORKMEMORY/work.log` 2026-11-07 14:12。

#### 16.2.2 hover 位移的真正问题不是推布局，而是文字横向跳

- **原文**：动效调研 §4 手法 2 的理由写作「用 `translate` 改布局 → 相邻行位移」；T3 原计划据此把问题定义为「推动布局」。
- **实测**：`transform` 从不参与布局，相邻元素不会被推动。真正的问题是元素内**文字随 `translateX(2px)` 整体横向跳动**，阅读锚点跟着鼠标漂移；同时触屏 tap 后 hover 态会粘住。
- **结论**：**【失效】**「推布局」不是主因。T3 移除 30 条 hover 位移，改由颜色/阴影/边框承载；保留 10 处非布局 `scale`/`rotate`；`.stat-badge` 的 `translateY(-2px)` 是唯一位移例外。验收改为「文字承载元素 hover 不得有位移」。
- **留痕**：计划 §7 #4 / #5；计划 T3 验收原文。

#### 16.2.3 循环动画实测 13 处，不是 4 处

- **原文**：动效调研前的估计为 **4 处** `infinite`（计划 §1 D1 引用该估计）。
- **实测**：22 个 `@keyframes`（`style.css` 19 + `workbench.css` 3）中 **13 处** `infinite`（style 12 + workbench 1）。
- **结论**：**【失效】** 估计值被实测取代。M1 删除/降级 5 个 keyframes，`infinite` 从 13 处降到 **7 处**白名单（光标 / 眨眼 / 待机 ×2 / marquee ×2 / 音频忙碌），全部补 `prefers-reduced-motion` 降级。
- **留痕**：调研 §8；计划 §1 D1；`WORKMEMORY/work.log` 2026-11-07。

#### 16.2.4 TTS 音色字形误判为「安全删除」（判错，不单独回滚）

- **原文**：第四批 B 类（#255）把 `static/views/player_and_tooltip.html:52/60` 的 👩/👨 判为「相邻已有 `Katja` / `Conrad` 文字 → 安全删除」。
- **复盘**：文字确实在，但对**不熟悉 TTS 音色**的使用者，字形是当时唯一能区分「哪个声音」的载体。删掉后该位置只剩一块纯色方块，音色选择失去视觉锚点。用户真机点开文库文章后无法分辨对应音频设置，实测复现。
- **结论**：**【判错·已承认】** 这不是「冗余装饰」，而是「某类身份/状态的唯一可辨载体」。B 类判据本身不完整，不是执行漂移。
- **处置**：不在本批单独回滚该处（已另派播放器托盘重构调研，单独改会和调研结论打架）；只把判据补强进 I1 执行口径。
- **判据补强（一句话，保留）**：**删除前不能只问「旁边有没有文字」，要问「这个字形是不是某类状态或身份的唯一可辨载体」。**
- **第二层根因（播放器托盘调研，2026-11-07）**：`static/style.css:3419-3431` 在 `≤768px` 断点给 `.voice-btn` 设 `font-size: 0`、`.vb-lbl { display: none }`。源码里 `Katja` / `Conrad` 文字确实还在，但**手机断点下字宽恒为 0**——当时只看了源码、没看断点，这是判错的第二层原因。
- **判据补强（三问，升级版）**：删除前必须连续过三问，任一答案是否定，字形就不是可安全删除的装饰：
  1. **断点问**：这个文字在窄屏断点下还在吗？`display: none` / `font-size: 0` / `visibility: hidden` 都算**不在**。
  2. **状态问**：这个字形是不是某类状态或身份（音色、模式、在线状态、性别等）的唯一可辨载体？
  3. **可达问**：`title` 在触屏不算文字；`aria-label` 只服务屏幕阅读器、不服务肉眼。二者都不能用来证明「旁边有文字」。
- **留痕**：本节；`WORKMEMORY/work.log` 2026-11-07 沉淀批次补记；播放器托盘调研 `docs/research/2026-11-07-player-tray-redesign-research.md`（PR #267，未合并）。

# ADR-0021: 继续走 Python —— 语言选择以运行时/交付为判据，「编辑期少犯错」用工具纪律解决

> **正式件:** `08-Projects/DeLector/01-ADR/0021-stay-on-python-language-choice-criteria.md`（vault）。本文件是仓内副本，内容与正式件同源（机械重新生成，未手抄）。
> **决策者:** Haoyu Xi ｜ **产出方式:** `/dfs-grill` 三面镜（技术/产品/交付）+ vault 梯子检索 + 用户拍板（Q1-A / Q2-A）。
> **要点:** 继续 Python 主体；**语言选择以运行时/交付为判据**，"编辑期少犯错"用工具纪律解决（14 条真实缺陷里仅 3 条可在编译期消除 ⇒ 21%）。替代投资四项已全部落地（CI 真启产物闸 / start.py 类型门禁 / 前端跨边界契约闸 / spaCy 惰性加载 −32%）。

- **状态**: Accepted（2026-10-10）
- **实施**: **无需代码改动**。本 ADR 的"实施"是**替代投资**：① **CI 真启产物闸**（最高优先）→ ② `mypy --strict` 收尾 → ③ `static/` 前端类型检查 → ④ spaCy 惰性加载（ADR-0018 §7.6 的 O0 杠杆）。
- **日期**: 2026-10-10
- **领域**: 语言/运行时选型 · 交付与运维面 · 工程纪律
- **决策者**: Haoyu Xi
- **上游**: **ADR-0018 §3.2（O1「换 HTTP 主体」永久否决 + 三条翻盘条件）· §4 D5（"Python 不可移除，spaCy 硬依赖；讨论的永远是边界而非替换"）· §7.2（D1 已执行 ⇒ 走 O0）**、ADR-0010（复用阶梯）、ADR-0020（桌面壳）、DEV-RULES §2.4（四端打包同步守卫）
- **本 ADR 的定位**: 回答一个**战略质疑**，并顺手补上一个原设计里的**判据缺口**——§3.2 的三条翻盘条件**只问运行时性能**，完全没覆盖"编辑期缺陷成本"这一维度，以致每次出运行期 bug 都会重新撬动语言选型。

---

## 1. Context

### 1.1 提案原文

> 我们还有必要继续走 python 路线吗？虽然开发快，但是很多问题不能在运行前就发现，经常出这种问题。改用 rust 或者 go 会不会能在编译阶段甚至编辑阶段就避免很多问题？

⇒ 诉求有二：（a）**少踩运行期坑**；（b）**在编译/编辑期就拦住问题**。

### 1.2 现状与规模（重写成本的地基）

| 面 | 规模 |
| --- | --- |
| `delector/`（Python 后端） | 62 文件 / **33,053 行** |
| `tools/`（基准/工具） | 18 文件 / 6,450 行 |
| `tests/`（回归资产） | 104 文件 / **37,771 行 / 1,505 个 `def test_`**；其中 **65 个测试文件直接白盒 `import delector.*`** |
| `static/`（前端） | 33,194 行（换后端语言**不减少**，仍是 webview/浏览器承载） |
| 硬依赖 | **`spaCy`（`de_core_news_sm`）—— Go/Rust 无等价物** |

### 1.3 上游已定案（本 ADR 必须与之自洽）

- **ADR-0018 §3.2**：O1（换 HTTP 主体、Python 降为 NLP sidecar）**否决**；翻盘条件三条缺一不可且需另开 ADR：① Python 解释器开销（剔除 spaCy 与 IO）占请求 p95 **>50%**；② 热点下沉实测**压不到**目标以下；③ **Android 侧双运行时方案给出可接受的体积与首启数据**。
- **ADR-0018 §4 D5**：**Python 不可移除**（spaCy 硬依赖）；讨论的永远是**边界**而非**替换**。
- **ADR-0018 §7.2**：D1 执行完毕 ⇒ 结论 **O0**（维持现状 + 便宜杠杆）。

## 2. Decision Drivers

- **诉求与手段的错配要查清**：用户要的是"少踩坑 / 对交付物有信心"，而"编译器能抓什么"是一个**可以被证伪的具体问题** —— 必须拿本仓真实缺陷清单去量，而不是用"类型系统更安全"这种不可证伪的话。
- **唯一作者 + 一天一版**：任何"数月产品不前进 + 回归资产作废"的方案，代价必须被显式计算。
- **spaCy 不可搬**：一旦主体换语言，形态只会退化成"两套 runtime + IPC"，而不是"更简单的交付物"。
- **可观测性不能降**：本仓多数事故靠"读产物 / 读构建脚本 / 读注册表"的闸发现；静态二进制会削弱这些能力。
- **判据要补全**：语言选型不应在每次运行期 bug 之后被重新撬动。

---

## 3. 证据：本次真实缺陷的**可证伪分类**（14 条）

判定：`a` = 编译器/类型系统编译期抓得住 · `b` = linter/vet 抓得住 · `c` = **换语言照样犯**。

| # | 本次真实缺陷 | 判定 | 理由 |
| --- | --- | --- | --- |
| 1 | **P0 死锁**：`evaluate_js`/`load_url` 在 `webview.start()` 之前调用 ⇒ 永久阻塞 | **c** | GUI 库的调用时序约束，两种语言都无类型可表达（Rust typestate 理论可行，但目标库不存在等价物） |
| 2 | 真实 UI 被塞进 `frameless/on_top/430×270` 的 splash 窗口 ⇒ 不可缩放 | **c** | 两个窗口同类型，塞错对象是**取值错误**，编译器无信息 |
| 3 | 数据目录兜底程序目录 ⇒ 升级覆盖 = 学习记录全空且零提示 | **c** | "哪个目录危险"是策略判断 |
| 4 | **红 master ×2**：跨进程量的大小关系被当**不变式** | **c** | **测试设计缺陷**，与语言无关 |
| 5 | 双重舍入导致的取整 flake | **c** | f64 照样双重舍入 |
| 6 | `except Exception: pass` 静默吞异常 | **b**（弱） | Go `errcheck` / Rust `#[must_use]` 会逼你处理 —— 但 `let _ =` / `_ = err` 仍是逃生舱 |
| 7 | 入口文件**裸奔**（CI 门禁只传显式目标 ⇒ `desktop.py`/`start.py` 根本没有类型检查）；`# type: ignore` 逃生舱 | **a** | `cargo build` / `go build ./...` 的全量覆盖是**结构性保证** ⇒ "CI 列了哪些文件"这类失败模式不存在 |
| 8 | 不可证伪结论（`N≈42`，对任意 `steady<42` 恒有正解） | **c** | 推理有效性，与语言无关 |
| 9 | 跨平台门禁假红（`ctypes.windll`/`winreg` 在 Linux runner 报错） | **a** | Go build tag / Rust `cfg` 把平台条件显式化 ⇒ "按本机平台挑 typeshed"这类错不存在 |
| 10 | 文档指针漂移成**假引用**（"理由见 ADR §7.4"而被引处语义相反） | **c** | 散文引用，无编译器可判 |
| 11 | 陈旧构建 / 版本号漂移（产物名 `v3.8.0`，App 实为 v5.16.0） | **c** | 发布流程问题 |
| 12 | 漏 DLL ⇒ 解压白屏（需 `hidden-import`/`collect-all` 清单 + 四端同步守卫，史上漏同步过 APK） | **c**（结构改善） | 编译器不抓"漏打包资源"；但静态单二进制基本**消掉"模块登记/依赖收集"这一整簇** |
| 13 | GBK 控制台打印非 ASCII 抛 `UnicodeEncodeError` | **c** | 换语言不抛异常但会**输出乱码** —— "崩溃"变"静默错"，未真正修 |
| 14 | 不带引号 heredoc 里反引号被命令替换，静默吃掉文档内容 | **c** | 与宿主语言无关 |

**计数**：`a+b` = **3 条**（#6/#7/#9）· `c` = **11 条**。
⇒ **换成 Rust/Go 至多在编译/编辑期消掉 ≈21%（3/14），其余 ≈79% 原样保留。**

**必须承认的真优势（不接受"什么都改善不了"）**：
- **#7** 全量覆盖由编译器保证 —— 这正是本仓最真实的类型债盲区（`desktop.py`/`start.py` 曾一度裸奔）；
- **#9** 平台条件编译显式化 —— 平台相关的假红/假绿从根上消失；
- **#12** 静态单二进制消掉"模块登记"这一簇成本。

**但**：这三条都是**工具与打包纪律**，在 Python 内即可获得；且它们与 §3.2 的三条翻盘条件**正交** —— 后者只问运行时性能，与"编辑期少犯错"无关。

## 4. Considered Options

### 4.1 Option O1′：换 Rust/Go 主体（Python 降为 NLP sidecar）—— ❌ 否决

- **交付物反而更复杂**：spaCy 必留 Python ⇒ 只剩两种形态，且都是 vault 已判的最贵形态 ——
  `subprocess + JSON`（冷启动 ~2s + 两套 runtime 打包）或 嵌入式 `cgo`/PyO3（**"cgo 交叉编译噩梦 + Windows DLL 链接地狱"**，且耦合从"解释器版本"升级为"链接期 ABI + `python3xx.dll` 搜索路径 + VC runtime"）。
- **Android 端**：**永久否决**（不是"待补数据"）——`android/app/build.gradle:83-93` 显示 **Chaquopy 只能装纯 Python 依赖、编译不了原生扩展**（`pydantic v2` 因 `pydantic-core` 是 Rust 而被锁回 v1）⇒ "Rust/Go 主体 + spaCy" 在 Android **无落地路径**；`:63-67` 的单 ABI 上限也已算过。⇒ §3.2 条件③ **不可满足**。
- **交付物自省被削弱**：本仓多数事故靠**读产物 / 读构建脚本 / 读注册表**的闸发现（`os.walk` 数 DLL、`unzip -l` 读 APK、验包探针）；静态二进制下产物是 blob（只能 `strings`/`nm`）；且 `try/except → launch.log + 弹窗` 这层"绝不静默失败"的保险在原生段 segfault 下**不可 recover**。
- **机会成本**：`delector/` 手工面 ≈2 万行 ⇒ 单人 **80–200 人日**；加 spaCy 桥接 + 四端打包重建 ⇒ **100–300 人日 ≈ 3–10 个月**，期间**产品 0 前进**（Android 仍 ⏸、内容不增、首启仍 2.6s），且**移植期同时失去 1,505 条测试的安全网**。
- **不触碰任何翻盘条件**：§3.2 三条一条都没被本提案满足。

### 4.2 Option O2（**采纳**）：继续 Python 主体 + 把 21% 用**工具纪律**买回来

- ✅ 投入产出比最高：`a+b` 那 3 条**全部可在 Python 内获得**（本仓 #9 的门禁本会话已落地）。
- ✅ 零回归资产损失、零产品停摆。
- ✅ 与 ADR-0018 §4 D5 完全自洽（讨论边界，不替换）。

### 4.3 Option O2/O3（ADR-0018 §3.3/§3.4：热点下沉 / 扩 Go 边界）—— 📌 维持"条件采纳"，本轮不动

- 判定门 AND 不成立（§7.2）⇒ **不触发**；若将来触发，只做**纯函数下沉**、**产物仍住同一打包位点**、每点配 `bench_*.py` 对照 + 一键回退，Android 恒留纯 Python。

## 5. Decision Outcome

| 前沿问题 | 拍板 | 含义 |
| --- | --- | --- |
| **Q1 要不要换主体** | **A：不换**（维持 Python + spaCy），把"对交付物的信心"投资到工具纪律 | 拒绝 O1′；本轮替代投资四件见 §6.1 |
| **Q2 语言选择的判据** | **A：写死判据** —— 语言选择以 **运行时/交付** 为判据；"编辑期少犯错"用**工具纪律**（闸 / 类型覆盖率 / CI）解决，**不作为换语言的判据** | 补上 §3.2 的判据缺口，防止每次运行期 bug 都重新撬动语言选型 |

**技术栈结论**：仍是 **Python（FastAPI + uvicorn + spaCy）+ 原生 JS + pywebview 桌面壳**。**不引入 Rust/Go 主体、不做 Python→sidecar 降级。**

> **判据的边界（防误用）**：本节**不**否定"编译期检查有价值"，只否定"把它当作换语言的理由"。若将来 **§3.2 三条翻盘条件**同时成立（**运行时性能**判据），换主体仍可另开 ADR 评估；但**"又出了个运行前没发现的 bug"不构成证据** —— 本次 P0（双击无窗口）类型系统根本看不见。

## 6. Consequences

### 6.1 替代投资（按优先级，**这就是本 ADR 的"实施"**）

1. **⭐ CI 真启产物闸（最高优先，两个席位独立得出同一结论）**：`build-release.yml` 目前**对产物零验证**（只 `pytest` 后打包）。应在 CI 上**真启一次 Windows 产物**：启动 → 校验 DeLector 身份（`/api/health` 的 `app` 字段）→ 断言 **≤N 秒干净退出**。**这是唯一能在作者双击之前抓住本次 P0 的闸。**
2. **`mypy --strict` 收尾**（`pyproject.toml` 已递延项）：把 `start.py` 那两处 `unused-ignore` 用签名/局部收窄替换后纳入门禁。
3. **`static/`（33k 行前端）加跨边界检查** ⇒ ✅ **已执行（2026-10-10，口径经实修订正）**：当前 JS↔Python 的外部边界才是真正的"跨边界误用"来源（这是编译期检查价值**真正成立**的那一类）。
   - **实修订正口径**：`tsc --checkJs` 扫全部 23 个 JS 文件实测 **219 条错误，其中 199 条为 `TS2339 Property 'X' does not exist on HTMLElement/Window`（缺 DOM/全局声明的噪音）** ⇒ 全量 `checkJs` 会沦为"永远红的噪音源"（本仓刚有过恒真/恒红门禁的教训）。⇒ 改为**抓真实跨边界误用**。
   - **主仪器（阻塞闸）**：`tools/check_frontend_api_contract.py` —— 用 **`delector.server.app.routes` 真实枚举**（124 条；新版 FastAPI 需递归 `_IncludedRouter.original_router.routes`）校验 `static/js` 的**真实调用写法**（`api()` 包装 ~104 处 / `fetch` / `doFetch` / `location.href`），模板插值与 `+` 拼接归一化为 `{}`，**未知端点非零退出**。当前 117 个调用点 → 109 可静态解析 → **全部匹配（PASS，未发现真缺陷）**；开发中修掉一处**工具假阳性**（`/api/listen/materials${levelParam}` 的插值实为查询串构造器）。
   - **次仪器（窄口径）**：`static/js/api-types.js`（**JSDoc typedef，形状从后端 handler 抄写**）+ `tsconfig.json` **显式 allowlist**（`api-types.js`、`update.js`）+ 固定版本 `typescript@5.6.3`；并加"allowlist 不得改成全量 glob"的守卫。
   - 两者都接进 ubuntu 质量闸作**阻塞步**，含归属/顺序守卫与两处变异自证。
4. **spaCy 惰性加载**（ADR-0018 §7.6 的 O0 杠杆，省 1.47s/2.6s）。

### 6.2 正面

- 零回归资产损失、零产品停摆；一天一版的迭代速度不被破坏。
- 补上判据缺口后，**"语言选型"这件事不再被每次运行期 bug 反复撬动**（本 ADR 存在的首要价值）。
- 把"信心"落到**可交付、可验证**的闸上（CI 真启产物），而不是落到语言信仰上。

### 6.3 负面 / 代价

- 放弃"全量类型覆盖的结构性保证"与"单一静态二进制"两项真优势 ⇒ 必须靠 §6.1 的闸**补上**，这是持续的纪律成本。
- 第 12 条那簇"模块登记/依赖收集"成本（`hidden-import` 清单 + 四端同步守卫 + 验包闸）**长期保留**。

## 7. Fog of War

- **[Unknown 1] Windows 产物在 CI 里能不能真启 GUI**：pywebview 需要真实桌面会话；CI runner 无 GUI ⇒ "真启产物闸"能否覆盖**窗口形态**尚未验证（可能需要 `--server-only` 口径 + 单独的真机 HITL）。**实施第 1 项前必须先探明**。
- **[Unknown 2] Android 端"永久否决"的时效**：本判定建立在 Chaquopy 不支持原生扩展、且 Android 端已 ⏸ 暂缓之上；若将来 Android 端重启且引入原生扩展支持，条件③ 需重新评估。
- **[Unknown 3] JS↔Python 边界的类型检查收益**：`static/` 33k 行加类型检查的实际拦截率未测（属 §6.1 第 3 项的投入产出验证）。

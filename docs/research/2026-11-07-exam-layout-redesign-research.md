# 备考页窄屏排版重构调研（393 / 360 双视口）

- 日期：2026-11-07
- 性质：只调研，不改代码；方案供决策，不进入实现
- 测量基线：本地运行中的 DeLector（`static/index.html` 版本 v5.21.1），工作树 `fix/poker-tap-flip @ f242b92`
- 测量工具：Edge headless + CDP，移动 UA、DPR 3、touch、视口 393×852 与 360×800
- 证据等级：`[A]` 本机实测；`[B]` 官方文档/官方截图/二手资料；`[U]` 无法验证

---

## 0. 结论先行

1. **三个症状是同一条根因链，不是三个独立问题。**
   `static/js/main.js:479` 用 `card.textContent = m.title` 把整张卡片的静态 DOM（序号 + 中文标签 + 德文副名）替换成一个纯文本节点，而 `delector/services/exam_catalog.py:32/40/46/52/58` 的标题里带 emoji。结果：
   - emoji 被注入；
   - 序号和德文副名被抹掉；
   - 纯文本节点成为 CSS Grid 的匿名项，被挤进 44px 宽的第一列，逐字换行；
   - 计数徽标成为第二列 Grid 项，和文本首行基线对齐，于是「18」飘在标题上方；
   - 行高从设计意图的 85px 涨到 133–182px。
   反证：没有接入目录的 06/07 两行（听力微训、长难句）保持静态结构，实测高度 85px，序号、中文、德文、对齐全部正常。

2. **标题溢出与模块无关。**
   `h2` 是 flex 项，默认 `min-width:auto`，长德文复合词没有断行机会；实测 `PRÜFUNGSDOMÄNE` 在 40px 下文本宽 376.8px，而返回按钮占位后可用宽度只有 224.5px（393）/ 191.5px（360）。超出的部分被祖先容器裁掉，所以页面没有横向滚动条，但文字右侧被切。源码实际文案是 **PRÜFUNGSDOMÄNE**；需求里写的 **PRÜFUNGSDOKUMENT** 更长（40px 下 444.5px），下文按更长的词做上限校验。

3. **四个数字是「内容总量」，不是「未完成量」。**
   18 = 8 个填表题 + 10 个短电邮场景（写作）；5 = 5 套听力套题；6 = 6 套阅读套题；54 = 34 个口语问答题 + 20 个请求题；702 = A1 词表词条。它们现在既无单位也无标签，且被 Grid 顶到标题上方。

4. **只修 `textContent` 还不够。**
   修完后行高回到 85px，7 行 = 595px；加上页头 248px，正文起点仍在 843px，首屏（可用 706px）看不到正文。要真正一屏，需要同时把页头压到约 190px、行高压到 60px。

5. **推荐方案 A：紧凑单列。**
   60px 行高 + 压缩页头：7 个入口全在一屏内，正文在首屏露出 96px（393）/ 49px（360），到正文顶部的滚动量从 1280px 降到 610/605px。保留单列目录、40px 级编辑排印、无边框无阴影的既有语言。

6. **emoji 建议直接从数据里删掉，不换成 sprite。**
   `static/icons/lucide-sprite.svg` 现有 16 个 symbol，全部是音量/播放/箭头/刷新等通用控件，没有笔、耳机、书、对话、列表这五个模块语义；要换图标得先补 5 个 symbol，而图标在这里只是装饰，与 ADR-0029 的「去装饰」冲突。中文模块名本身足够清楚，序号 01–07 已提供视觉锚点。

7. **标题策略：返回按钮独占一行，标题占满整行。**
   `clamp(1.75rem, 7.8vw, 2.5rem)` 在 393 得 30.6px、360 得 28.1px；`PRÜFUNGSDOKUMENT` 按字距修正后约 338px / 302px，均小于可用宽度 345px / 312px。不要用 `white-space:nowrap`、`text-overflow:ellipsis` 或 `word-break:break-all`。

8. **数字要带单位。**
   推荐「18 题」「5 套」「6 套」「54 题」「702 词」，套题可加二级信息「5 套 · 75 题」。单位由后端目录返回，前端只负责拼装，避免再次硬编码。

### 2.4 症状二：标题溢出的根因

实测值（393 视口）：

| 项 | 数值 |
| --- | --- |
| `.exam-container` 内容宽 | 345px |
| 返回按钮宽 | 100.5px |
| `.exam-topbar` gap | 20px |
| h2 起点 x | 144.5px |
| h2 可用宽度 | 224.5px |
| h2 实际宽 | 376.8px |
| h2 右边界 | 521.3px |
| 超出 topbar 右边界（369） | 152.3px |
| 超出视口右边界（393） | 128.3px |

360 视口：可用宽度 191.5px，h2 宽仍为 376.8px，超出 topbar 185.3px。

计算样式：

```
white-space: normal
word-break: normal
overflow-wrap: normal
hyphens: manual
display: block（flex 子项）
min-width: auto（默认，未覆盖）
```

根因是「flex 子项 + 不可断的德文复合词」：h2 的 min-content 宽度就是最长词的宽度，flex 不允许它缩到 376.8px 以下；祖先 `.view` 裁掉溢出，所以没有横向滚动条。

| 36px | 349.2px | 400.1px |
| 34px | 329.8px | 377.8px |
| 32px | 310.4px | 355.6px |

- 40px 时 `PRÜFUNGSDOMÄNE` 加字距后为 376.8px，与 DOM 实测完全一致，验证了测量口径。
- 只要返回按钮仍与标题同行，可用宽度只有 224.5/191.5px，标题必须降到 22px 左右才能放下，显然不可接受。
- 因此标题修复的第一步是**改变布局关系**，不是继续缩字号。

### 2.5 症状三：单列太长与数字漂浮的机制

卡片 CSS 是 `display:grid; grid-template-columns: 2.75rem 1fr; gap:1rem; align-items:baseline`。静态结构本应是：

```
[01]  [写作专项]
      [(Schreiben)]
```

执行 `card.textContent = "📝 写作专项 (Schreiben)"` 后，DOM 变成：

```
<button class="exam-module-card">
  "📝 写作专项 (Schreiben)"   ← 匿名 Grid 项，落入 2.75rem 第一列
  <span class="exam-module-count">18</span>  ← 第二列，baseline 对齐
</button>
```

后果：

1. 文本节点在 44px 宽的第一列里逐字换行，形成「📝 / 写作 / 专项 / (Schreiben)」3–5 行；
2. 计数徽标在第二列第一行，视觉上浮在标题上方；
3. 序号 01–05 和德文副名的独立样式全部失效；
4. 卡片高度由 85px 涨到 133–182px；
5. `aria-label` 和选中态的 `.exam-module-index` 也一起丢失。

未被目录覆盖的 06/07 保持 85px，是最直接的反证。

### 2.6 数字语义

| 模块 | 当前显示 | 真实含义 | 建议写法 |
| --- | --- | --- | --- |
| 写作专项 | 18 | 8 个 Teil 1 填表题 + 10 个 Teil 2 短电邮场景 | `18 题`，可附 `8 填表 + 10 短电邮` |
| 听力模考 | 5 | 5 套听力套题 | `5 套`，可附 `75 题` |
| 阅读工坊 | 6 | 6 套阅读套题 | `6 套`，可附 `90 题` |
| 口语问答 | 54 | 34 个 Teil 2 问答题 + 20 个 Teil 3 请求题 | `54 题` |
| 官方考纲词表 | 702 | A1 官方词表 702 个词条 | `702 词` |

- 这些数字都是**内容总量**，不是用户进度、未完成数或错题数。
- A2 词表 736、B1 词表 1617；`formatExamCount` 会把 1617 格式化为 `1.6k`，单位仍需补上，否则 `1.6k` 同样不可读。
- 当前徽标 `font-size:0.75rem`、`mono`、`color:var(--ink-faint)`，样式本身符合元数据定位；问题只在语义、位置和单位。

### 2.7 现有移动端规则

- `static/style.css` 中 `exam-*` 相关规则没有任何 `max-width` 媒体查询；393/360 完全复用桌面尺寸。
- 全局 `@media (max-width:640px)` 存在，但不覆盖 `.exam-container` 的 40/24/64 padding、40px 标题、85px 行高。
- 结论：不是断点写错，而是**没有为这个页面写窄屏策略**。

### 3.2 正向模式

**AnkiWeb Shared Decks —— 极限密度，但无层级**

- 16 个分类用行内链接排列，12px 字号、18px 行距、3px 行间、44px 组间，全部落在约 92px 的高度内。
- 优点：一屏能扫完 16 个入口，几乎没有滚动。
- 代价：没有图标、没有副标题、没有计数，分类之间靠逗号/换行区分；无法承载「18 题」这类元数据。
- 对备考页的启示：如果只需要「模块名」，密度可以极高；但我们需要中文名 + 德文副名 + 题量，必须用行而不是行内链接。

**Bilibili —— 横向分类条**

- 15 个入口排在一行，单项 62.9–77.5px 宽、41.9px 高，14.7px 字号；393 视口约 6.2 个可见，其余横滑。
- 优点：42px 就解决了「入口多」的问题，正文可以立刻开始。
- 代价：约 60% 的入口不在首屏，依赖用户知道可以横滑；没有计数。
- 对备考页的启示：可作为「索引 + 正文分流」的参考（方案 C），但不适合作为 7 个模块的唯一入口，因为会藏掉 3–4 个。

**Linear Docs —— 48px 分组导航**

- 行高 48px，16/24px 字号，嵌套缩进 40px，360px 高度内可见约 9 行；每行有图标，无计数。
- 优点：48px 是「16px 文字 + 单行标题」的舒适下限，7 行仅 336px。
- 代价：单行标题放不下中文 + 德文两行；需要 60px 才能容纳两行。
- 对备考页的启示：60px 行高并不激进，仍低于 Notion/Apple Books 的卡片高度一个数量级。

**Google Play —— 55px 底栏**

- 底部 4 个标签，单项 98.3×55px，14px 字号；顶部胶囊 32px 高、横滑。
- 对备考页的启示：55–60px 是成熟的触控行高区间，7 行 60px 完全在可用范围内。

### 3.3 反向模式

**Notion Marketplace / Notion Help —— 大卡不能做 7 入口索引**

- 单列卡片高度 202/250/309px，393 视口一屏只能放 1 张；一屏放 7 个需要滚 6 次。
- Notion Help 用 28px 胶囊压缩了分类，但下方仍是 186–206px 的大卡；胶囊只解决「分类名」，不解决「入口列表」。
- 对备考页的启示：当前 133–182px 的行已经接近 Notion 卡片高度，属于「卡片化的列表」，不是目录。

**Apple Books —— 横向轮播不是索引**

- 165.5×333px 的封面卡，393 视口 2.2 张可见，靠横滑浏览；排名和作者在卡内。
- 对备考页的启示：封面/大图轮播适合「浏览发现」，不适合「7 个功能入口全部可见」。

**Spotify —— 卡片架**

- 224×316px 卡片，约 2 张可见，横向滚动；一屏只能看一个 shelf。
- 对备考页的启示：图片驱动的分类页密度天然低；备考页没有封面需求，不应模仿。

### 3.4 文档参考

- **Anki 移动端牌组列表**：官方手册明确「decks 和 subdecks 以列表显示，并显示当天的 New、Learn、Due 三列数字」。这是「列表行 + 右对齐数字」最贴近我们需求的形态；数字有明确列标题，不漂浮。[B]
- **Things 3**：官方页面与 App Store 截图呈现单列任务行、无副标题、44pt 级触控目标；上一份外部参考库已在桌面视口实测过其列表密度。移动端列表密度高，但信息层级只有一行。[B]
- **Duolingo**：路径节点是「一次一个单元」的进度模型，不是 6–8 个并列入口，不能直接借用。[B]

### 3.5 对备考页的五条硬约束

1. **48px 是单行列表的下限，60px 是双行列表的合理值。** 7×60=420px，能在 654px 的 360 视口里留出正文空间。
2. **页头必须 ≤200px。** 否则 7 行再紧凑也会把正文挤出首屏。当前页头 247.78px。
3. **数字必须右对齐并带单位。** 左对齐/居中都会与标题争夺视线；Anki 的三列数字是最成熟的参照。
4. **双列在 360 视口每格只有约 151px。** 2 列可行（151px > 140px 安全线），3 列不可行（约 97px，放不下「官方考纲词表」）。
5. **横向索引会藏掉 3–4 个入口。** 除非产品明确接受「先看正文、再横滑找模块」，否则不作为主方案。

## 4. 方案

三个方案共享同一个 P0 前置修复，否则任何排版都会被 `textContent` 再次破坏：

- 删除 `static/js/main.js:479` 的 `card.textContent = m.title`；静态 `exam.html` 已有 7 个模块的完整标签，目录只负责计数与面板接线。
- 如果确实需要目录驱动标题，改为结构化更新：
  - 目录返回 `label`（中文）与 `de`（德文）两个字段；

| 首屏可见入口 | 7/7 | 7/7 | 3.7/3.4 |

| 到正文顶滚动量（393/360） | 610 / 605px | 526 / 521px | 248 / 243px |
| 360 视口挤压风险 | 低 | 低（151px 格子） | 低 |
| 与「去装饰 + 编辑式排印」冲突 | 最低 | 中等（网格/图标） | 中等（控件感） |
| 实现改动量 | 小（CSS + 删一行 + 数据） | 中（网格 + 可选图标） | 中（横滑 + 选中同步） |
| 主要风险 | 标题字号下降 | 双列削弱纵向节奏 | 入口被藏 |

**推荐 A。** 理由：

1. 它直接解决「7 个入口一屏 + 正文首屏可见」的核心诉求，同时保留单列目录的编辑式身份；
2. 改动集中在 CSS 和一个错误的赋值语句，回归面最小；
3. 60px 行高有 Linear（48px）、Google Play（55px）两个实测锚点，不是拍脑袋；
4. B 的双列虽然正文露出更多，但会引入网格/图标语言，和 ADR-0029 的「去边框、去装饰」相抵；
5. C 的横滑会藏掉 3–4 个入口，不适合作为主入口页。

如果产品更看重「正文优先」而不是「目录优先」，可以把 B 作为备选；C 不建议。

## 5. 三件必须一起回答的小事

### 5.1 emoji 怎么处理

**推荐：直接删除，不换 sprite。**

- 删除范围：`delector/services/exam_catalog.py` 第 32、40、46、52、58、69、82 行的 7 个 emoji。
- 删除后卡片仍有：序号 01–07、中文模块名、德文副名、题量。四个信息通道，中文名是主语义，不依赖任何图形符号，符合 I1。
- `static/icons/lucide-sprite.svg` 当前只有 16 个 symbol（音量、播放、暂停、快进、旋转、删除、上传、箭头、sparkles、关闭、刷新、加号等通用控件），**没有**笔、耳机、书、对话、列表。要「换成 sprite」必须先补 5 个 symbol，属于新增资产，不是现成替换。
- 即使补了 symbol，图标在这里也只是装饰：既不是唯一语义载体，也不提供操作提示；与 ADR-0029 的「去装饰」方向冲突，且会增加一次 sprite 维护成本。
- 如果未来选了方案 B 且产品坚持要图标：在每格左侧放 16px `<svg><use href="#icon-...">`，`aria-hidden="true"`，中文名和序号保留；同时补 `pencil`、`headphones`、`book-open`、`message-circle`、`list-checks` 五个 symbol。不要在方案 A 里加。

### 5.2 标题溢出怎么修

**推荐：返回按钮独占一行 + 标题占满整行 + 字号 clamp。**

```css
@media (max-width: 640px) {
  .exam-container {
    padding: 20px 20px 48px;
  }
  .exam-topbar {
    display: block;
    margin-bottom: 14px;
    padding-bottom: 10px;
  }
  .exam-topbar .btn {
    display: inline-flex;
    height: 32px;
    margin-bottom: 8px;
  }
  .exam-topbar h2 {
    font-size: clamp(1.75rem, 7.8vw, 2.5rem); /* 393 → 30.6px；360 → 28.1px */
    line-height: 1.06;
    letter-spacing: -0.02em;
    overflow-wrap: anywhere; /* 仅作兜底，正常不触发 */
  }
}
```

验证：

- 393：可用宽度 345px；`PRÜFUNGSDOMÄNE` 30.6px 下约 296px；`PRÜFUNGSDOKUMENT` 约 338px，均不溢出。
- 360：可用宽度 312px；`PRÜFUNGSDOMÄNE` 约 271px；`PRÜFUNGSDOKUMENT` 约 302px，均不溢出（后者余量约 10px）。
- 标题仍会自然折成两行（「备考 ·」+ 德文词），这是可接受的编辑式排版；不要强行单行。

**不推荐：**

- `white-space: nowrap` + `text-overflow: ellipsis`：会切掉德文词尾，品牌词不完整。
- `word-break: break-all`：会把 `PRÜFUNGS|DOMÄNE` 从任意字母处断开，德语复合词的语义读法被破坏。
- 只缩字号、不改 flex 关系：返回按钮同行时可用宽度只有 224.5/191.5px，标题要降到 22px 才放得下。
- 缩短文案：`PRÜFUNGSDOMÄNE` 是这一页的身份标识，不建议为了排版改词；如果产品愿意，可改为 `Prüfungsbereich`（更短），但这是文案决策，不是排版修复。

### 5.3 数字的语义怎么表达

**推荐：后端返回单位，前端拼装；套题可带二级题量。**

目录字段建议：

```json
{
  "id": "hoeren",
  "count": 5,
  "unit": "套",
  "count_detail": "75 题"
}
```

前端：

```js
badge.textContent = `${formatExamCount(m.count)} ${m.unit}`;
badge.setAttribute("aria-label", `共 ${m.count} ${m.unit}` + (m.count_detail ? `，${m.count_detail}` : ""));
```

展示：

| 模块 | 徽标 | 可选二级信息 |
| --- | --- | --- |
| 写作专项 | `18 题` | `8 填表 + 10 短电邮` |
| 听力模考 | `5 套` | `75 题` |
| 阅读工坊 | `6 套` | `90 题` |
| 口语问答 | `54 题` | `34 问答 + 20 请求` |
| 官方考纲词表 | `702 词` | — |

- 如果不想加 `count_detail` 字段，至少要有 `unit`；`5 套`、`6 套` 已经可读，`18`、`54`、`702` 仍然不可读。
- `formatExamCount` 对 >999 的值返回 `1.6k`，单位要跟在后面：`1.6k 词`。如果产品更在意精确性，可在词表模块禁用 k 缩写，显示 `1617 词`；12px mono 下 `1617 词` 约 54px，仍放得下。
- 数字列右对齐，与中文名之间保持至少 12px 空隙；不要把数字放在标题上方，也不要居中。

## 7. 未验证与边界

1. **只测了 Blink（Edge headless）**，不是 Android WebView。系统字体替换、`font-family` 回退、DPR 取整可能造成 1–3px 差异，不影响 60px 行的结论。
2. **只测了 A1 的 5 个目录模块**；A2/B1 只有词表，标题长度更短，风险更低。
3. **安全区未叠加**：方案 A 在 360 设备叠加 24px 底部安全区时，正文露出从 49px 降到 25px，7 行仍完整；若安全区超过 30px，建议把 360 行高降到 58px。
4. **字体加载**：标题宽度在 `document.fonts.ready` 后测量；如果 Playfair Display 加载失败回退 Georgia，宽度会有小幅变化，`overflow-wrap:anywhere` 作为兜底。
5. **外部产品**：微信读书、得到无法通过登录墙/客户端渲染，未取得实测数据；Spotify 强制近 800px 画布，只作形态参考。所有 `[B]` 条目未在本机重新测量。
6. **用户描述与源码的差异**：需求写的是 `PRÜFUNGSDOKUMENT`，源码实际是 `PRÜFUNGSDOMÄNE`。本报告按更长的 `PRÜFUNGSDOKUMENT` 做上限校验；若产品后续确实改成该词，5.2 的数值仍然成立。

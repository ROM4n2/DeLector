## 踩坑与教训

- **Android Chaquopy 漏模块**（09-04/09-06）：现象=APK 启动 `ModuleNotFoundError`；根因=打包清单逐个维护易漏（漏 `routes_rtc`/`routes_a2`）；解法=改整目录拷贝 + 打包注册守卫（`test_all_backend_modules_registered_in_all_packaging_targets`）钉死。
- **测试库 env 串扰 `no such table: exam_trials`**（09-10 初现 → 09-26 根因精确化）：现象=Windows 2 例失败而 CI 长期绿；根因=测试模块**模块级**直赋 `DATABASE_PATH` 永久污染 env、使后到模块的 `setdefault` 失效、库又被删成空库；解法=契约 C1–C4 + 根因级 AST 守卫（`tests/test_test_isolation.py`）。ubuntu 因 `os.remove` 抛 `OSError` 被吞而**掩盖**了跨平台的顺序耦合。
- **pydantic v2 专属 API（`model_copy`）**（09-14）：现象=Android 长难句全源 500；根因=Chaquopy 锁 `pydantic<2.0`（需 Rust 的 `pydantic-core` 无法编译），v1 无 `model_copy`；解法=直接构造模型 + regex 跨端守卫（桌面 pydantic 2.x 无法复现）。
- **探针 fixture 形状失真**（09-14）：现象=揭示句法树渲染 `[object Object]`；根因=探针 fixture 用数组 `field_texts`，与真实 API 的**字符串**形状不符 → 恒走错误分支漏检；解法=fixture 改真实形状 + 新增断言。
- **Python from-import 按值拷贝不可变对象**（09-15）：现象=spaCy 诊断 `error` 永远为空；根因=`from x import _err` 拿到导入时初始空串，`global` 重绑定不改旧引用；解法=改 `get_spacy_load_error()` getter 实时读。
- **spaCy E050：dist-info 缺失**（09-15）：现象=真机 `Can't find model 'de_core_news_sm'`；根因=spaCy 3.8 `is_package()` 只认 pip 元数据（`.dist-info`）、不碰文件系统，CI 漏拷平级 `.dist-info`；解法=连拷 dist-info + APK 探针 `dist-info-complete` 守卫。**五连发（v5.7.0→v5.7.6）才触到真根因**。
- **setup-android 默认装 `tools` 包**（09-15）：现象=CI Android job 12s 失败、Publish 被跳过；根因=runner 镜像 cmdline-tools 升 20.0 移除废弃 `tools` 包；解法=显式覆盖 `packages`（装 compileSdk 34 所需组件）。
- **mypy 配置放 `.ini` 会 GBK 崩**（09-13）：解法=配置落 `pyproject.toml [tool.mypy]`（强制 UTF-8）。
- **`git checkout --` 整文件回退未提交改动**（09-06）：教训=破坏性 git 命令在 TDD 中禁用。
- **fastapi ≥0.141 行为变更**（09-24）：现象=路由守卫「全量 115 条 missing」误报；根因=`route.path` 已含 prefix（再拼会双拼）+ `include_router` 改嵌套（`app.routes` 里无 `path`）；解法=比对键改 `app.openapi()["paths"]` 的 HTTP 语义键 `(path, METHOD)`。
- **工具包名拼写 `deletor` vs `delector`**（09-18）：教训=长命令手打包名必错，改变量/拼接规避。
- **单点变异可能被另一处修复免疫**（09-26）：方法论=必须做**配对变异**（污染源 + 还原受害者）才能造出红/绿对比、坐实根因链。
